# 图像这一块
下面把 **2D 生图（Diffusion）** 和 **3D 生成/重建（NeRF → 3DGS）** 两条线放在一起，按年份串起来

## 2015–2019：前夜

- **2015**：Sohl-Dickstein 等人首次提出扩散概率模型的思想，但当时效果和实用性都不如 GAN。
- **2014–2019**：GAN（GAN、StyleGAN、BigGAN）主导图像生成，画质提升快，但训练不稳定、模式坍缩问题明显。
- **3D 侧**：主流还是传统几何重建 + 神经渲染的早期探索，NeRF 还没出现。 [arthurchiao](https://arthurchiao.art/blog/rise-of-diffusion-based-models-zh/)

## 2020–2021：Diffusion 奠基，NeRF 出现

### 2D 生图
- **2020.06**：Ho 等人提出 **DDPM**，把“加噪—去噪”训练范式做稳定，扩散模型第一次真正能和 GAN 掰手腕。 [aws.amazon](https://aws.amazon.com/blogs/physical-ai/3d-gaussian-splatting-performant-3d-scene-reconstruction-at-scale/)
- **2020.10**：Song 等提出 **DDIM**，把采样从 1000 步降到几十步，开启少步生成研究。 [aws.amazon](https://aws.amazon.com/blogs/physical-ai/3d-gaussian-splatting-performant-3d-scene-reconstruction-at-scale/)
- **2021**：Improved DDPM、Classifier-Free Guidance 等陆续出现，CFG 成为后来所有 text-to-image 模型的标配。 [aws.amazon](https://aws.amazon.com/blogs/physical-ai/3d-gaussian-splatting-performant-3d-scene-reconstruction-at-scale/)
- **2021.12**：Rombach 等提出 **Latent Diffusion（LDM）**，把扩散搬到 VAE 潜空间，为 Stable Diffusion 铺路。 [aws.amazon](https://aws.amazon.com/blogs/physical-ai/3d-gaussian-splatting-performant-3d-scene-reconstruction-at-scale/)

### 3D 侧
- **2020**：Mildenhall 等提出 **NeRF**，用 MLP 隐式表示场景，实现高质量新视角合成，成为 3D 重建的新范式。 [arthurchiao](https://arthurchiao.art/blog/rise-of-diffusion-based-models-zh/)
- **2021–2022**：Instant-NGP、TensoRF 等加速 NeRF，但本质上仍是隐式表示，渲染和编辑都不够灵活。 [arxiv](https://arxiv.org/html/2401.03890v9)

## 2022：Stable Diffusion 引爆 AIGC

### 2D 生图
- **2022 上半年**：DALL·E 2、Imagen 相继发布，扩散模型正式成为 text-to-image 主流。 [github](https://github.com/Ahmedn1/gaussian-splatting-benchmark/blob/main/LEARNING_JOURNAL.md)
- **2022.08**：Stability AI 开源 **Stable Diffusion 1.x**，把 LDM 落到消费级 GPU，引发社区爆炸式创新（LoRA、ControlNet、各种 WebUI）。 [aws.amazon](https://aws.amazon.com/blogs/physical-ai/3d-gaussian-splatting-performant-3d-scene-reconstruction-at-scale/)
- **2022**：SD 2.x 进一步提升分辨率和文本对齐。 [yobitel](https://yobitel.com/knowledge-base/diffusion-models)

### 3D 侧
- **2022**：DreamFusion 等工作出现，用预训练 2D 扩散模型作为先验，通过 SDS 优化 NeRF，实现 text-to-3D，第一次把 Diffusion 和 3D 生成连起来。 [gitcode.csdn](https://gitcode.csdn.net/69c330a10a2f6a37c59a171f.html)
- 但此时 3D 生成仍以 NeRF 为载体，速度和可编辑性受限。 [mdpi](https://www.mdpi.com/2079-9292/15/4/828)

## 2023：DiT 出现，3DGS 横空出世

### 2D 生图
- **2023.07**：SDXL 发布，分辨率提升到 1024，双 CLIP 文本编码器，语义理解更强。 [awesome.papernotes](https://awesome.papernotes.org/era4_foundation_models/2020_ddpm/)
- **2023**：Peebles & Xie 提出 **DiT（Diffusion Transformer）**，把 U-Net 换成 Transformer，证明扩散模型也能像 LLM 一样随规模平滑提升。 [aws.amazon](https://aws.amazon.com/blogs/physical-ai/3d-gaussian-splatting-performant-3d-scene-reconstruction-at-scale/)
- **2023**：Consistency Models、LCM 等蒸馏方法出现，把生成压缩到 1–4 步，逼近实时。 [aws.amazon](https://aws.amazon.com/blogs/physical-ai/3d-gaussian-splatting-performant-3d-scene-reconstruction-at-scale/)
- **2023**：Rectified Flow / Flow Matching 理论成熟，为 SD3、FLUX 铺路。 [aws.amazon](https://aws.amazon.com/blogs/physical-ai/3d-gaussian-splatting-performant-3d-scene-reconstruction-at-scale/)

### 3D 侧
- **2023.08**：Kerbl 等在 SIGGRAPH 提出 **3D Gaussian Splatting（3DGS）**，用显式 3D 高斯基元 + 可微光栅化，实现实时、高保真渲染，迅速取代 NeRF 成为新热点。 [arthurchiao](https://arthurchiao.art/blog/rise-of-diffusion-based-models-zh/)
- **2023 下半年**：3DGS 开源后，学术界和工业界跟进极快，衍生出大量加速、压缩、编辑、生成的工作。 [alphaxiv](https://www.alphaxiv.org/ko/overview/2210.00379v7)
- **2023**：DreamGaussian、GaussianDreamer 等把扩散先验从 NeRF 迁移到 3DGS，text-to-3D 速度大幅提升。 [gitcode.csdn](https://gitcode.csdn.net/69c330a10a2f6a37c59a171f.html)

## 2024：DiT + Flow Matching 成主流，3DGS 全面开花

### 2D 生图
- **2024.06**：Stable Diffusion 3 发布，采用 **MMDiT + Rectified Flow**，正式把 DiT 和 Flow Matching 推到前台。 [aws.amazon](https://aws.amazon.com/blogs/physical-ai/3d-gaussian-splatting-performant-3d-scene-reconstruction-at-scale/)
- **2024.08**：Black Forest Labs 发布 **FLUX.1**，12B 参数的 Rectified Flow Transformer，成为开源侧新标杆。 [awesome.papernotes](https://awesome.papernotes.org/era4_foundation_models/2020_ddpm/)
- **2024**：视频扩散（Sora、可灵等）爆发，DiT 架构从图像扩展到视频。 [aws.amazon](https://aws.amazon.com/blogs/physical-ai/3d-gaussian-splatting-performant-3d-scene-reconstruction-at-scale/)
- **2024**：边缘端轻量化（MobileDiffusion 等）开始出现，扩散模型走向手机端。 [awesome.papernotes](https://awesome.papernotes.org/era4_foundation_models/2020_ddpm/)

### 3D 侧
- **2024**：3DGS 成为 3D 重建和生成的主流表示，大量工作集中在：
  - **加速与压缩**：让 3DGS 能跑在端侧和大规模场景。 [alphaxiv](https://www.alphaxiv.org/ko/overview/2210.00379v7)
  - **编辑**：GaussianEditor 等，用 2D 扩散模型驱动 3D 场景编辑。
  - **生成**：前馈式 text/image-to-3DGS 模型兴起，速度从分钟级降到秒级。 [gitcode.csdn](https://gitcode.csdn.net/69c330a10a2f6a37c59a171f.html)
- **2024**：3DGS 在自动驾驶、数字孪生、影视、游戏资产管线中开始落地。 [alphaxiv](https://www.alphaxiv.org/ko/overview/2210.00379v7)

## 2025–2026：多模态统一 + 3DGS 工业化

### 2D 生图
- **2025**：GPT Image、Gemini 图像、Qwen-Image 等**原生多模态生图**兴起，文本理解、图像生成、多轮编辑放进同一模型。
- **2025–2026**：蒸馏、量化、边缘部署成为重点，1–4 步生成、移动端实时生图成为现实。 [awesome.papernotes](https://awesome.papernotes.org/era4_foundation_models/2020_ddpm/)
- **2026**：学术界开始系统梳理多模态视觉理解与生成的统一框架。

### 3D 侧
- **2025–2026**：3DGS 进入**工业化深耕期**：
  - **大规模场景**：城市级、自动驾驶级 3DGS 重建与压缩。 [alphaxiv](https://www.alphaxiv.org/ko/overview/2210.00379v7)
  - **生成式编辑**：文本驱动的多视角一致 3D 场景编辑成熟。
  - **物理与动画**：3DGS + 物理仿真、材质、驱动动画结合，静态场景“动起来”。
  - **应用综述**：2025–2026 年出现多篇系统综述，把 3DGS 的分割、编辑、生成三大方向整理成体系。

## 一张图看懂两条线的交汇

```
2015        扩散思想提出
2020        DDPM ──────────────── NeRF
2021        DDIM / CFG / LDM ───── NeRF 加速
2022        Stable Diffusion ───── DreamFusion (Diffusion→NeRF)
2023        DiT / SDXL ─────────── 3DGS 出现 (Diffusion→3DGS)
2024        SD3 / FLUX (DiT+RF) ── 3DGS 编辑/生成/压缩爆发
2025-26     原生多模态生图 ─────── 3DGS 工业化 + 生成式编辑
```

可以看到一个清晰的规律：**2D 侧从 U-Net 走向 DiT + Flow Matching，3D 侧从 NeRF 走向 3DGS，而两者在 2022–2023 年通过“扩散先验 + 3D 表示”深度绑定，到 2024–2026 年各自成熟并开始互相反哺。** 

# 文字

- 2017 年：Transformer 提出，用注意力机制构建序列模型，为后来的大语言模型提供架构基础。 [en.wikipedia](https://en.wikipedia.org/wiki/Large_language_model)
- 2018–2020 年：GPT-1、GPT-2、GPT-3 相继出现，确立“自回归预测 + 大规模预训练”路线，文本生成逐渐从简单续写发展到通过提示词完成多种任务。 [datacamp](https://www.datacamp.com/blog/history-and-evolution-of-large-language-models)
- 2022 年：ChatGPT 发布，结合指令训练与人类反馈强化学习（RLHF），推动语言模型从“会续写”走向“能对话、遵循指令”。 [datacamp](https://www.datacamp.com/blog/history-and-evolution-of-large-language-models)
- 2023 年起：工具调用与 Agent 系统兴起，将语言模型与检索、代码执行、文件处理等外部能力结合，开始处理多步任务。 [datacamp](https://www.datacamp.com/blog/history-and-evolution-of-large-language-models)
- 2024–2025 年：以 OpenAI o1、DeepSeek-R1 为代表的推理模型发展，通过专门训练和增加推理时计算，增强复杂问题求解能力。 [datacamp](https://www.datacamp.com/blog/history-and-evolution-of-large-language-models)
- 2025–2026 年：多模态与任务执行进一步结合，发展重点从单次回答扩展到连接应用、处理文件、推进工作流。 [openai](https://openai.com/index/hello-gpt-4o/)

# 音频

音频不是一条单线，而是语音合成、声音转换、音乐与音效生成、实时语音交互几条路线并行发展。

- 2016 年：WaveNet 通过自回归方式直接生成音频波形，成为神经音频生成的重要节点。 [raw.githubusercontent](https://raw.githubusercontent.com/mlresearch/v235/main/assets/cherep24a/cherep24a.pdf)
- 2022 年前后：AudioLM 等推动音频语言建模，将声音转换成可预测的表示序列，让语言模型式方法用于音频生成。 [rapidops](https://www.rapidops.com/ai-tracker/audiolm/)
- 2023 年前后：社区中 so-vits-svc、Bert-VITS2 等项目受到关注。前者主要做声音转换，后者做文字转语音，两者不是严格的前后代关系。 [techshinobi](https://techshinobi.org/posts/voice-vits/)
- 2023 年：MusicGen、AudioCraft 推动文本生成音乐与音效，音频生成从“合成人声”扩展到“根据描述创作声音”。 [pragnakalp](https://www.pragnakalp.com/generate-music-using-metas-musicgen-on-colab/)
- 2024 年：GPT-SoVITS 推动少样本、零样本语音合成与声音克隆；CosyVoice 将语言模型生成语音 token 与 Flow Matching 声学生成结合。 [github](https://github.com/RVC-Boss/GPT-SoVITS)
- 2024 年：GPT-4o、Moshi 推动原生音频与实时语音交互；Moshi 进一步探索全双工对话，支持同时建模用户声音和自身语音输出。 [openai](https://openai.com/index/hello-gpt-4o/)
- 2024 年底以后：CosyVoice 2 等进一步优化流式合成，重点转向低延迟、分块连续性，以及流式与非流式生成的统一。 [huggingface](https://huggingface.co/papers/2412.10117)
- 2025–2026 年：语音生成继续向声音可控、音色克隆、流式输出和多模态融合发展。 [thursdai](https://thursdai.news/topics/voice-ai)

现在比较流行就是suno，还有elevenlabs

文字：文本续写 → 指令对话 → 推理增强 → 工具调用与任务执行

音频：波形生成 → 语音合成与声音转换 → 声音克隆／音乐音效生成
      → 音频语言模型 → 流式与全双工语音交互


# 关于实现

## 图像

### 一、Diffusion：先从小型 DDPM 开始

| 路线 | 推荐项目 | 适合做什么 | 当前硬件适配 |
|---|---|---|---|
| 二维点分布 DDPM | [DDPM_Tutorial](https://github.com/RuiZhang2016/DDPM_Tutorial) | 理解加噪、噪声预测、反向采样，使用小型 MLP | 首选，明确支持 CPU |
| MNIST 图片生成 | [denoising-diffusion](https://github.com/danilodjor/denoising-diffusion) | 用小型 U-Net 从噪声生成手写数字 | 可以尝试，需缩小默认配置 |
| 预训练文生图 | [stable-diffusion.cpp](https://github.com/leejet/stable-diffusion.cpp) | 加载模型，体验 prompt、采样、量化与 CPU 推理 | 支持 CPU，但速度取决于模型和处理器 |

这些项目分别面向教学实现、DDPM 训练和扩散模型推理，不是同一种工具。 [github](https://github.com/RuiZhang2016/DDPM_Tutorial)

建议顺序：

```text
二维点分布 DDPM
    ↓
MNIST 小型 DDPM
    ↓
增加数字类别条件
    ↓
体验预训练 Stable Diffusion 推理
```

先完整跑通“加噪 → 训练预测噪声 → 反向采样”，不必一开始就追求高分辨率文生图。二维项目默认支持 CPU；MNIST 项目的默认配置较大，需要调整。 [github](https://github.com/RuiZhang2016/DDPM_Tutorial)

### 二、3D 高斯喷溅：先查看和渲染，再考虑重建训练

| 路线 | 推荐项目／方式 | 当前硬件适配 |
|---|---|---|
| 查看现成三维高斯场景 | [antimatter15/splat](https://github.com/antimatter15/splat) | 可以先试，流畅度取决于核显和场景大小 |
| 在线体验 | [https://antimatter15.com/splat/](https://antimatter15.com/splat/) | 最低上手门槛，无需安装 CUDA |
| 修改渲染代码 | 基于上述 WebGL 查看器 | 适合练习投影、椭圆高斯绘制、透明度混合 |
| 二维高斯拟合图片 | 自己写小型 PyTorch CPU 实验 | 可作为教学练习，控制图片尺寸和高斯数量 |
| 从多张照片训练完整 3DGS | [原版 gaussian-splatting](https://github.com/graphdeco-inria/gaussian-splatting) | 不适合当前机器，原版优化器依赖 CUDA GPU |

WebGL 查看器不要求 NVIDIA 独显，但仍使用图形硬件，不等于纯 CPU 渲染；原版 3DGS 的训练与浏览器查看是不同的流程。 [github](https://github.com/antimatter15/splat)

建议顺序：

```text
浏览器打开小型场景
    ↓
阅读、修改 WebGL 渲染代码
    ↓
手工放置少量三维高斯并渲染
    ↓
可选：用二维高斯拟合低分辨率图片
```

注意：这里的“二维高斯拟合图片”是简化教学实验，不是完整 3DGS 重建，也不是特指论文里的 2D Gaussian Splatting。

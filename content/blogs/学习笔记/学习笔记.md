## 1. CRUD：Create, Read, Update, Delete


| 缩写 | 英文 | 中文 | 含义 | 常见 SQL | 常见 HTTP (REST API) |
| :--- | :--- | :--- | :--- | :--- | :--- |
| **C** | Create | 创建/新增 | 新建一条数据 | INSERT | POST |
| **R** | Read | 读取/查询 | 查询数据 | SELECT | GET |
| **U** | Update | 更新/修改 | 修改已有数据 | UPDATE | PUT / PATCH |
| **D** | Delete | 删除 | 删除数据 | DELETE | DELETE |

常用于数据库，任何需要管理数据的系统，比如后台管理系统、REST API、ORM、文件系统，都可以用 CRUD 来描述基本操作。

## 2. REST API
典型的REST API：
```
GET    /api/v1/users         获取用户列表
POST   /api/v1/users         创建用户
GET    /api/v1/users/1       获取 id=1 的用户
PUT    /api/v1/users/1       整体更新 id=1 的用户
PATCH  /api/v1/users/1       部分更新 id=1 的用户
DELETE /api/v1/users/1       删除 id=1 的用户
```
如果我有 POST、PATCH、GET、DELETE 等一整套接口，按资源来设计，那就是典型的 REST API。 如果只是暴露了一堆 HTTP 方法可调用的接口，那更宽泛地叫 HTTP API，严格说要看是否符合 REST 风格。

所以说之前我们实习的项目，介于REST API和HTTP API之间吧，风格的话也是有点像。

## 3. 菲茨定律

核心定义

该定律用于预测一个人快速移动到目标区域所需的时间。简单来说：移动时间取决于目标的“距离”和目标的“大小”。

数学公式（香农公式）

$T = a + blog_2 (\frac{D}{W}  + 1)$

• T：到达目标所需的总时间（移动时间）。
• a, b：与具体人体器官或操作设备相关的经验常数（由实验测得）。
• D：起点到目标中心的距离（Distance）。
• W：目标在移动方向上的宽度（Width）。

常见的实验就是两个方块，在不同的位置，先点一个，再点另一个，都点完后，会重新刷新在随机位置

有两个用途吧：
- 一个就是用来测试人的手眼协调度，所以可能用于健康检测，或者是FPS天赋测试这种地方
- 另一个就是界面设计，简单来说就是button的大小以及界面的交互，不能花太多时间，同时界面边缘的情况也需要考虑

## 4. CMS

### CMS是什么

**CMS = Content Management System（内容管理系统）**

一句话解释：它是一种让你**不写代码也能管理网站内容**的软件。

CMS 就像一个**自动整理的图书馆管理员**：

- 你把文章、图片、视频（内容）交给它
- 它负责存到哪里、怎么排版、什么时候显示
- 你只需要专注「写什么」，不用管「怎么放」

### 为什么到处都能看到

因为**现在大半个互联网都跑在 CMS 上**：

| 你看到的地方 | 背后可能就是 |
| --- | --- |
| 各类博客、企业官网 | WordPress（占全球网站约 40%+） |
| 新闻门户 | Drupal、Joomla |
| 商城、店铺后台 | Shopify、Magento |
| 公司内部文档站 | Confluence、Notion（广义上也算） |
| 国内的很多网站 | 织梦、帝国 CMS |

原因很简单：**从零手写一个网站的登录、发文、评论、权限管理，成本太高了**。CMS 把这些通用功能打包好，普通编辑点几下按钮就能发布内容——就像没有人为了吃面包先去种小麦一样。

然后博客的流程其实就是一个比较简单的CMS模型

经典 CMS 的定义包含四个职能，你的博客把它们分配给了不同的工具：

| CMS 职能 | WordPress 里谁负责 | 你的博客里谁负责 |
| --- | --- | --- |
| 内容存储 | 数据库（MySQL） | Git 仓库（一堆 .md 文件） |
| 编辑界面 | 网页后台 | 本地编辑器（VS Code / Obsidian） |
| 发布流程 | 点「发布」按钮 | push 触发 CI |
| 排版渲染 | 服务器运行时实时渲染 | 构建时一次性生成静态 HTML |

所以说「模板」只是其中的**展示层**——它相当于 WordPress 里的主题，真正干活的是整条管线。

## 那它到底算不算 CMS？

**严格派会说不算**，因为缺了 CMS 最核心的东西：

- **运行时管理**——文章不是存在系统里被动态调用，而是编译成死文件。想改一个错别字也要重新走一遍构建。
- **图形后台**——它默认使用者会写 Markdown、会用 Git。如果想让不懂技术的人投稿，这条流水线立刻失灵。
- **媒体库、定时发布、草稿审核**这些「管理」功能，全靠你自己想办法（或者没有）。

**宽泛派会说算**，因为 CMS 的本质诉求——「内容和展示分离，写的人不用管代码」——你确实完整实现了，而且实现得比 WordPress 更干净：每篇文章就是一个纯文本文件，永生（Markdown 五十年后也能读，MySQL 转储文件可不好说）。

## 5. 哈希表
就是两数之和问题，比较好的解决方案
```python
def twoSum(nums, target):
    seen = {}                      # 值 -> 下标
    for i, x in enumerate(nums):
        need = target - x
        if need in seen:           # 一次查询,不是一遍遍历
            return [seen[need], i]
        seen[x] = i                # 先查再存,天然避免用自己
    return []
```
然后其中enumerate函数的参数是这样的，就是传一个序列进去，然后从头开始枚举
```python
enumerate(sequence, [start=0])
```
